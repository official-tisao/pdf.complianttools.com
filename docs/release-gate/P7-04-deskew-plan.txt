P7-04 Deskew Measurement Plan — Evidence for Gate

Done-when under test: "deskew measurably improves a deliberately-skewed fixture set."

Fixture set: fixtures/p7-04/skew-*.png (8 pages, one upright control)
  Angles: -8, -4.5, -2, 0 (control), +1.5, +3, +6, +11 degrees
  Ground truth: fixtures/p7-04/skew-manifest.json, written by the generator rather
  than derived from the estimator, so the comparison is against an independent fact.
  Each page is 900x640 of synthetic horizontal text rules plus a solid block, so the
  estimator is not relying on ruled lines alone.

Method: node scripts/measure-skew.mjs
  Decodes each fixture to raw grayscale pixels, runs the SHIPPED estimator
  (estimateSkew) and correction (deskew) from packages/engine/dist, and records:
    - detectedDegrees   what the estimator reports for the page as drawn
    - residualBefore    |detected - applied| (how honest the detector is)
    - residualAfter     |angle of the corrected page| (how far it is from upright)

Pass criteria (all must hold, per fixture):
  residualBefore <= 0.5 deg   the estimator recovers the drawn angle
  residualAfter  <= 0.5 deg   the corrected page is upright within tolerance
  For the upright control, the residual must not GROW: an already-straight page
  must be returned untouched, not re-encoded.

Result (see P7-04-evidence.json, regenerated by the script):
  8 fixtures, 7 skewed
  worst residualAfter: 0.05 deg
  mean residualBefore: 0.018 deg
  status: PASS

Regeneration trigger: any FAIL, or any change to packages/engine/src/scan-deskew.ts
  -> node scripts/fixtures:skew -> node scripts/measure:skew -> review the diff

Scope of this evidence, stated plainly:
  This is a MEASUREMENT over synthetic pages. It is NOT physical-device evidence.
  The fixtures exercise the estimator and the correction; they do not reproduce
  lens distortion, uneven lighting, or page curl, because they are drawn rather
  than photographed. A PASS here is a claim about the algorithm, not about the
  behaviour of the tool on a real phone.

Not covered by this evidence, and still open:
  - Perspective (four-point) correction. README 4.5 says "perspective deskew";
    this gate covers rotation only. The gap is recorded in PLAN.md P7-04 and in
    docs/WORKSTREAM-F-GATE.md rather than claimed as done.
  - Camera capture end to end on hardware. The engine seam and the UI are covered
    by unit and browser tests; no phone has been used to photograph a page.
